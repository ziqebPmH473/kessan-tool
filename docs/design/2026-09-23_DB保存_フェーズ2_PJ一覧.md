# DB保存 フェーズ2：上のタブをやめ、種別＞PJ一覧で作業を選ぶ（2026-09-23 実装済み）

Notion: 「DB保存 フェーズ2」。前提はフェーズ1（`docs/impl/2026-09-23_DB保存_フェーズ1.md`）。

## 決まっていること（すみぽん 2026-09-23）

- 種別をプルダウンで選ぶ → その種別のPJ一覧が出る → 「新規」で空のPJを始める。
- 一覧の表示：決算〜株価は「作成日 銘柄名」、YT動画は「作成日 テーマ」。並びは作成日時の新しい順（更新日ではない）。並び替えは後で設定タブに。
- 株価分析は今後ほかの用途でも使う（1年後・9か月後の現状分析を追加予定）。
- スマホでは通しの作業は無理。画像を出すところまでが現実的。

## 画面

```
[種別 ▼ 決算]  [PJ ▼ 2026/09/23 7203 トヨタ自動車]  [＋新規]  [削除]        ● サーバーに保存済み
──────────────────────────────────────────────────────────────────────────
（選んだ種別のレイアウト。中身は今の各タブのまま）
```

- 上の4タブ（決算・個別銘柄・株価・YT動画）を消し、上の1行に置き換える。`switchMode(kind)` はそのまま使う（表示の出し分けは変えない）。
- 種別を変えると **空のPJ** で開く（新規を押したのと同じ）。前に開いていたPJへ引き戻さない（種別を変えるのは新しく作るときなので）。続きをやるときはPJのプルダウンから選ぶ。
- 空のPJは、何か入力したりファイルを入れたりした時点で初めて行を作る（種別を眺めただけでは増えない）。
- **ブラウザのタブごとに別のPJを開ける**。同じブラウザの別タブどうしでも引き戻さない（決算の信越化学と決算のレーザーテックを並行して作れる）。開いているPJはタブ（sessionStorage）が覚える。開き直し（リロード）は同じPJに戻る。新しいタブは空の決算で始まる。
- 同じPJを2つのタブ（や2台）で開いて両方で書いたときだけ、フェーズ1の「別の端末と食い違い」の帯が出る。
- PJのプルダウンは「作成日 見出し」。見出しが空（銘柄名がまだ無い）のときは「（名前なし）」。
- 「新規」：種別を選んだ状態で押す → 空のPJを作って開く（欄は既定値、ファイルは無し）。作成日は押した時刻。
- 「削除」：確認してから消す。サーバーの行とそのPJのファイルも消す。**複製は今回つけない**（要るなら後で）。
- 1行に収まらない（テーマが長くて切れる）場合は、見てから上下2段にするか決める。
- 株価分析の「用途」：株価分析の行に `sub`（用途）を持たせ、既定は「株価分析」。1年後・9か月後の現状分析は、用途を足してレイアウトの一部（プロンプトや見出し）を切り替える想定。今回は入れ物（`sub` の欄と、一覧の見出しに用途を添える）だけ用意し、用途の中身は別タスク。
- 右上の保存の札はそのまま。

## データ

- 行の id：`p:<kind>:<作成時刻>`（例 `p:earnings:20260923-2015-ab12`）。フェーズ1の `p:earnings` などは「その種別の最初のPJ」として、初回にこの形の id へ移す（サーバー側で1回だけ。旧 id の行は消す）。
- 行の json に `meta:{created, title, sub}` を持たせる。`title` は今の `ktTabTitle()`、`created` は ISO 文字列。サーバーの `created_at` は行を作った時刻なので、移行した行だけ `meta.created` を localStorage 側の値（無ければ移行時刻）で入れる。
- `shared` 行に「種別ごとに最後に開いたPJ」`current:{earnings:id, ...}` を持つ。使うのは初回移行の直後（移行した行を開く）だけで、ふだんの起動には使わない。
- ファイル（R2 / IndexedDB）のキーは PJ ごとに分ける：`<ns>/<pid>/<key>`。フェーズ1のキー（`files/earn` など）は最初のPJのものとして移す（R2 は copy → delete、IndexedDB は put → delete）。
  - 横動画の `gen:` プレフィックス（`ytKey`）は不要になる。YT動画のPJは kind=yt、株価分析の横動画は kind=price のPJの中。`YT_CTX` は「いま開いている種別が yt か」に置き換え、`kt-yt-fields-*` の入れ替えは消す。
  - ナレスラのひな形 `tpl` だけは PJ をまたいで共通なので `yn/_common/tpl`。
- `/api/state`：`GET ?list=1` で json 抜き（id, kind, title, version, created_at, meta）を返す。`GET ?id=` で1行。今の「全部返す」は初回移行にだけ使う。行が増えても起動が重くならないように。
- 起動：`shared` と、各種別の current の行だけ読む。ほかのPJはプルダウンで選んだときに読む。

## PJの切り替え（画面の中身の入れ替え）

1. いまのPJを保存する（`saveStateNow()` → 送り切るまで待つ `KTStore.flush()`）。
2. 新しいPJの行を読み、その種別の欄（`TAB_IO[kind]` の roots にある欄）へ `tabIoApplyFields()` で入れる。他の種別の欄は触らない。
3. その種別のファイルを読み直す：決算＝`restoreEarnFiles()`、株価・YT動画＝`vdRestoreTts()` `yaRestore()` `ynRestore()`（横動画の一式）、サムネ背景。
4. `switchMode(kind)` と、各タブの「復元後の描き直し」（`window.onload` の後半でやっていること）を、その種別ぶんだけ呼ぶ。
   - ここが一番手間。`window.onload` の後半を「種別ごとの復元関数」に分けて、起動時もPJ切り替え時も同じ関数を通す。

欄の所属（どの欄がどの種別か）は `TAB_IO` の roots で決めているが、横動画のパネル `#yt-root` は開いているタブで親が変わる。フェーズ2では **`#yt-root` を kind=price と kind=yt の両方の欄として扱い、値は「いま開いているPJ」のもの** と決める（保存時に開いていない側の行には書かない）。

## スマホ

- 種別や機能をスマホで制限しない。同じ画面・同じ種別が使える（同期しているのだから、どの端末からでも同じことができる）。
- 見た目の調整（プレビューの縮小など）は今のまま。

## ファイルの容量

- PJの中でファイルを入れ直したときは、同じキーに上書きするので古いものは残らない（今までと同じ）。
- 容量が増えるのはPJの数に応じてだけ。PJを削除すると、そのPJのファイルも消える。R2 の無料枠は 10GB。
- 「戻す」ための控え（横動画の割り当てなど）は今までどおり端末内（IndexedDB）だけ。サーバーには置かない。
