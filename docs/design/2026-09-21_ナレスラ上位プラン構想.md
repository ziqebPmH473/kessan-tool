# ナレスラ上位プラン構想：「文」を単位にした編集（2026-09-21 メモ）

状態：構想のみ。今すぐは作らない。kessan-tool の横動画機能を実際に使いながら、要件を固める。
きっかけ：横動画の「並べて表示」（左＝スライドと演出、右＝文の一覧）を使ってみて、ユーザーが「これがあれば編集が変わる気がする」と発言。

## 何が価値か

タイムライン（秒）ではなく、**話している文**を単位にして、カット・スライドの切替・演出を1つの画面で扱えること。

- スライドを**パーツ（まとまり）に分解**する（AIが画像から位置を読む → 枠に番号）
- 文の範囲に、**スライドの切替**を割り当てる（AIが提案 → 1文ずつ動かして直す）
- 文の範囲に、**演出**（ズーム／四角枠／ハイライト／下線／資料やチャートの差し込み）を割り当てる。対象はパーツの番号
- **カット**も同じ文の一覧で行う（AIの判定 → チェックで直す、文の一部はドラッグで削る）
- 文の一覧とスライド（パーツの枠つき）を**横に並べて**見る

AIが下書きを作り、人は文単位で直すだけ、という流れになる。

## ナレスラに入れるときの位置づけ

- 上位（高額）プランの機能。全部を移すのではなく、上の「文を単位にした編集」の部分だけ。
- 株価分析に固有のもの（調査・出典の管理・レポート・noteの有料範囲）は kessan-tool に残す。
- ナレスラは公開済みの製品（実ユーザー・Stripe本番）。既存の .svpz / IndexedDB / Firestore を壊さない形で足す。
  AIの呼び出し先・無料枠・プランとの関係は、設計時に決める。

## kessan-tool 側で確かめられたこと（設計の材料）

- Gemini は、画像のスライドからパーツの位置を正確に返せる（0〜1000の枠）。
- 時刻の正確さは Whisper（large-v3）、文章の正確さは Gemini。両者を文字単位で突き合わせると一致率97〜99%。
- 切り口は「削る部分の声の立ち上がり〜次に残す部分の声の立ち上がり」。無音への吸着は、先の無音まで飛んで次の文の頭を削らないよう条件が要る。
  短い相槌は前後の吸着先が同じになり長さが潰れるので、逃げ道が要る。
- 演出の時間は**カット後の時間**で考えさせる（AIに渡す時刻・長さ、3秒未満の判定、表示）。書き出す時刻は元の音声の時刻。
- 資料やチャートを差し込んでいる間は、ズームも強調も外す。
- 出典の量は長さに比例（カット後1分あたり約0.8件、1件5〜8秒、20秒以上あける）。
- 一覧UIで必要になった操作：切替を1文ずつ動かす／演出の始まり・終わりを1文ずつ動かす／種類を変える／消す／
  対象はパーツ番号で示す／その時間に話している文を添える／帯は1種類（スライド単位）にする。
