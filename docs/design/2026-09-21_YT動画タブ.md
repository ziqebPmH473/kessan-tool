## 1. 目的

株価分析の横動画の仕組み（音声 → スライド → カット → ナレスラ → 投稿文）を、テーマを問わない動画にも使えるようにする。対象は、すみっこマネー大学で出す動画。

- 一番上のタブの「📉 株価分析」の右に「🎬 YT動画」を足す。
- 調査タブだけ中身を差し替え、音声以降は同じ画面を使う。
- 最後に、note（無料・YouTubeを差し込む）とブログの記事データを作るタブを足す。

## 2. ユーザーと決めたこと

| 項目 | 決定 |
|---|---|
| 対象の範囲 | すみっこマネー大学の別テーマまで。チャンネルに依存する文言は設定欄に出す |
| 調査の流れ | テーマを入力 → ChatGPTと会話して出したレポートを貼る（形は自由・プロンプトなし）→ 「①構成と出典を付ける」プロンプトを投げて結果を貼る → ②ファクト／③再CK／④修正を繰り返す → 音声以降は株と同じ |
| ①の出力 | レポートの本文は書き換えない。先頭に構成の表、本文に［出典n］の印、末尾に出典一覧、の3つだけ足す |
| ①を投げる先 | 調べた会話と同じチャットを勧める（実際に見た資料のURLが出る）。プロンプトにはレポート全文を差し込み、別チャットでも使える形にする。ファクトチェックは今と同じく別チャット |
| データの持ち方 | 株の横動画と YT動画で、1本ずつ別に持つ。過去分はエクスポートで残す |
| 記事の元データ | ファクトチェック済みの動画資料。Gemini API とプロンプトコピーの両方。YouTubeのURLは後から欄に入れて差し込む。noteは無料記事 |
| 最後のスライドの note案内＋QR | QR用のURLがあるときだけ付ける |
| チャート（TradingView）の差し込み | 残す（AIがティッカーを出したときだけ） |
| サムネ | 3段（Gemのルールどおり）。中段は**この動画の主題**（下記） |

### サムネの中段（ユーザー指摘 2026-09-21）

- 中段は、動画の中の注目点ではなく、**その動画の主題**（何が分かる動画か・何を分析する動画か）を、視聴者が見たくなる言葉で書く。6〜9文字。
- 株の横動画で中段が銘柄名なのは、銘柄名が「何の動画か」を表すから。YT動画ではテーマがその役割。
- 動画の中で取り上げる個別の材料・指標・要因は、中段に書かない（使うなら上段・下段の側）。
- 上段（感情・問題提起）と下段（抽象的な問い）は、Gemの原文の役割のまま、中段の主題に向けて作る。
- プロンプトには「この動画の主題：（テーマ欄の内容）」を明示して渡す。動画資料から推測させない（資料の中で目立つ数字や用語が中段に来やすくなる）。
- ユーザーが挙げた例（半導体関連株の次に来るテーマ）は理解の確認用。プロンプトには例を入れない。

## 3. 技術判断で決めた前提

- **音声タブ以降のUIと関数は、株価分析とYT動画で共通の1組**。今あるものをそのまま使う。片方で直したことは、両方に効く。
- YT動画で違う箇所は、同じ関数の中で「株か・YT動画か」を見て分ける。新しく作るのは、調査タブ（テーマ・レポート・①構成と出典）と記事タブだけ。分ける箇所は §7-3〜7-5 に挙げたものに限り、勝手に増やさない。
- 分けた箇所（プロンプトの文言など）を直すときは、もう片方にも同じ直しが要るかをその都度確認する。
- 横動画の画面と関数（約160個）は複製しない（IDが固定で、複製すると二重管理になる）。
- 動画の種類を `YT_CTX`（`'stock'` か `'gen'`）で持ち、切り替えで部品と保存先を入れ替える（`thCtxSync` と同じ考え方）。
- 株側の IndexedDB のキーと localStorage の欄は今のまま。既存データの移行は要らない。
- 新しい部品のIDは `yg-` で始める。

## 4. 現状

- 横動画の左側は `#mode-price` の動画タブの中（`#vd-orient-y`）に1組だけ。右ペインは `#capture-area-price` の中で `setMode` で切り替える。
- 保存：入力欄は localStorage（`YT_PERSIST_IDS`）。音声とカットは IndexedDB `kessanTool-ytAudio`（`audio` `state`）。スライドなどは `kessanTool-ytNare`（`slides` `plan` `tpl` `srcimg` `srcedit`）。読み書きは `yaPut/yaGet`・`ynPut/ynGet` に集まっている。エクスポートは `hidden.yt`。
- 株に依存している関数・定数：`ytResearchPrompt`／`ytFactCheckPrompt`（「レポート1〜2章は省略」の文）／`ytFreeReport`（6か所）／`YT_CHAPTERS`（3か所）／`ytIntent`／`vdBasicInfo('vd')`（4か所）／`getDir()` の出し分け／`getName()`・`getTicker()`（約100か所）／読みがなの取り出し／`YT_SLIDE_DESIGNER`／`YT_POST_RULES` 末尾の読み替え／出典のチャート種別／QR用のURL。

## 7. 詳細設計

### 7-1. 動画の種類の切り替え（土台）

- `let YT_CTX='stock'`、`const ytGen=()=>YT_CTX==='gen'`。
- IndexedDB：`yaPut/yaGet/ynPut/ynGet` の中でキーを `ytKey(k)` に通す。gen は `'gen:'+k`、stock はそのまま。`tpl`（ナレスラのひな形）は共通で、接頭辞なし。
- 入力欄：`YT_PERSIST_IDS` のうち、設定タブの共通項目（`yt-p-fixed` `ya-ctx` `yt-months` `yt-nlm-min`）以外が「作品ごとの欄」。切り替え時に、今の値を `localStorage['kt-yt-fields-'+旧ctx]` に退避し、新しい ctx の値を欄に入れて `saveState()`。
- メモリ上の状態（`YA` `YN` `YS`）：切り替え前に保留中の保存を流す（`_yaSaveTimer` を即時実行する `yaFlush()` を足す）。そのあと、起動時・インポート時と同じ読み直しを呼ぶ。再生中の音声は止める。
- サムネイル：`th-ctx` に `gen` を足す。保存先は `yg-th-text`／`yg-th-preset`。

### 7-2. タブと画面

- `.mode-tabs` に `<button data-mode="yt">🎬 YT動画</button>`。左側の空の入れ物 `#mode-yt`。
- `switchMode('yt')`：横動画のパネル（`ytBuildTabHtml` の出力を包む要素に `id="yt-root"`）を `appendChild` で `#mode-yt` に移す（値やイベントは残る）。右側は `#capture-area-price` を表示し `ytPaneMode()` の表示に。「スライド」「動画（縦）」のタブボタンは隠す。`YT_CTX='gen'`。
- ほかのモードへ出るとき：パネルを `#vd-orient-y` に戻し、`YT_CTX='stock'`、右ペインのボタンを元に戻す。
- 内側タブ：調査／音声／スライド／カット／ナレスラ／投稿文／記事／設定（「記事」は gen のときだけ）。

### 7-3. 調査タブ（gen 用の別パネル `yg-pane-research`）

1. テーマ欄 `yg-theme`（1行）。シリーズ名は今の `yt-series`（gen の既定値は空）。
2. レポートの貼り付け欄 `yg-report`（形は自由。📋貼り付けボタン）。
3. ボタン：💬 ①構成と出典を付ける（`ygStructPrompt`）／✅ ②ファクト／🔁 ③再CK／🔧 ④修正。
4. 動画資料の貼り付け欄は `yt-doc` を共用（作品ごとの欄）。貼ると②を自動でコピー。🔗出典のリンク確認は今のまま。

①のプロンプトの骨子（文面は相談する）：
- 役割は構成作家。目的に `ytIntent()`。
- 本文は書き換えない。足すのは、先頭の `## 構成` の表（章番号｜章の名前｜扱う内容）、本文の `［出典n］` の印、末尾の `## 出典一覧` の3つだけ。
- 出典一覧の列、出力の形、PDFの扱いの文は、今の調査プロンプトから流用。
- 先頭に、読み間違えやすい言葉の読みがなの欄。
- 「同じチャットに投げる」という案内は、プロンプトではなく画面の注記に書く。

②ファクトチェック：`ytFactCheckPrompt` を ctx で分ける。gen では「レポートは確認済みなので省く」の段を外し、構成の表も確認対象。禁止事項の列挙は、売買を促す表現と視聴者への行動要求だけ。

### 7-4. 構成の読み取りと差し替え

- `ytChapters()`：stock は `YT_CHAPTERS`、gen は `yt-doc` の `## 構成` の表を読んで `[{no,name,what}]`。読めないときは空の配列と画面の注意。
- `YT_CHAPTERS` を直接使っている3か所を `ytChapters()` に置き換える。スライドの枚数の文言は `章の数＋1` から作る。
- gen の扱い：
  - `ytIntent()`：`「テーマ」を解説する動画（シリーズ名があれば付ける）`
  - `vdBasicInfo('vd')` の4か所：`テーマ：…` の1行
  - `ytFreeReport()`：`fr.ok` が false の道を通す。throw している箇所だけ分岐
  - 読みがな：動画資料の「読みがな」欄から。欄の見出しは「読み間違えやすい言葉」
  - `getName()` を使う表示・ファイル名・投稿文：`ytTitleName()`（gen はテーマ、stock は銘柄名）
- `YT_SLIDE_DESIGNER`：冒頭の役割の一文と、チャート・まとめ（QR）の段を差し込み式に。QRの段はQR用のURLがあるときだけ。
- 演出の割り当てのチャートは gen でも残す（AIがティッカーを出したときだけ）。

### 7-5. 投稿文

- `YT_POST_RULES` の本文（Gemの原文）はそのまま。末尾の【この動画での読み替え】だけ gen 用を用意。
- サムネは3段、記法 `上段：中段：下段` と色マーカーはそのまま。中段は §2「サムネの中段」のとおり。
- タグ：「銘柄名と証券コードは必ず」の文を外す。
- X の先頭行 `【#銘柄名（コード）】` は gen では付けない。

### 7-6. 記事タブ（gen のみ）

- 元データ：ファクトチェック済みの `yt-doc`（構成の表・出典の印・出典一覧を除いた本文）。
- ボタン：note用・ブログ用のそれぞれに「プロンプトをコピー」「🤖 Gemini APIで作る」。
- 出力：【タイトル】【本　文】【ハッシュタグ】の3ブロック。note用は表を禁止、ブログ用は表を使う。
- YouTube のURLは `yt-p-yturl`。note用は冒頭の段落のあとにURLを単独の段落で（貼ってEnterでカードになる）。ブログ用は `[動画を見る](URL)`（埋め込みの形は sumikko-money 側を確認してから決める）。
- URLが空でも本文は作れ、あとから差し込み直せる。差し込みは何度押しても増えない（関連記事の挿入と同じ）。
- 既存の売買表現チェックを通す。

### 7-7. エクスポート／インポート

- タブ一覧に `yt:{label:'YT動画',roots:['#mode-yt'],nameId:'yg-theme'}`。
- `hidden.yt` は今の形のまま。gen の状態で書き出して gen に戻す。ファイルに `ctx` を記録し、違うタブで読もうとしたら止めて知らせる。

## 8. 実装手順

1段階＝1コミット。各段階のあとに `node --check` と株側の回帰確認。プロンプトの文面は、各段階の最初に案を出して相談する。

1. 土台：`YT_CTX`、`ytKey`、欄の退避と復元、`yaFlush`、読み直し（見た目は変えない）
2. タブの追加、パネルの移動、右ペインの出し分け、`thCtxSync` の3つ目
3. 調査タブ（gen）：テーマ、レポート、①〜④
4. `ytChapters()` ほか、gen 用の差し替え（音声・スライド・カット・ナレスラ）
5. 投稿文の読み替え（gen）
6. 記事タブ
7. エクスポート／インポート
8. `docs/impl` の実装記録、Notion の更新

## 10. 既存仕様を壊すリスク

- **切り替え時の保存の取り違え**がいちばん大きい（保留中のタイマー、非同期の読み込み中の切り替え）。切り替えは「保存を流す → ctx を変える → 読み直す」を1つの `async` 関数にまとめ、処理中はタブを押せなくする。
- パネルを移すことで、`#mode-price` 配下を前提にした処理（エクスポートの `roots`、`ytSyncTabs`）がずれる可能性。
- `thCtxSync` が2つの保存先を前提にしている箇所。

## 11. 注意点

- ブログでの YouTube の埋め込みの形は、sumikko-money 側で未確認。記事タブの着手時に確認する。
- 起票済みの「ブログ記事用のデータ出力」タスクとは対象が違う（あちらは株の記事）。
- 別セッションが `index.html` の投稿文まわりを変更中。着手時の最新を土台にする。

## 12. やってはいけないこと

- 横動画の関数・画面を複製する
- 株側の保存キーの名前を変える
- Gemの原文を書き換える
- プロンプトを相談なしに確定する／許可の一文や例をプロンプトに足す
- 複数の段階を1コミットに混ぜる
- ほかのDBに起票する
