# D1 の履歴（projects_hist）を掃除する手順

2026-11-05 に、本番の D1（`kessan-tool`）が無料プランの上限 500MB にほぼ達し（499.68MB）、保存（PUT /api/state）が HTTP 503／500 で失敗し続けた。
内訳は現在の PJ が 28MB、履歴 `projects_hist` が 420MB（1 PJ につき 30 版）。決算 PJ の `ev-viz-settings` に表紙画像 2 枚（base64 JPEG、合計約 420KB）が入っていて、保存のたびに履歴にも丸ごと残っていたのが原因。

Claude は本番 D1 への書き込みを安全装置に止められるので、以下はユーザーが PowerShell（`C:\work\kessan-tool`）で実行する。

## 1. いまの大きさを見る（読み取りだけ）

```powershell
npx.cmd wrangler d1 execute kessan-tool --remote --command "SELECT 'projects' AS t, count(*) AS n, sum(length(json)) AS bytes FROM projects UNION ALL SELECT 'projects_hist', count(*), sum(length(json)) FROM projects_hist"
```

## 2. 履歴を PJ ごとに直近 2 版だけ残して消す

```powershell
npx.cmd wrangler d1 execute kessan-tool --remote -y --command "DELETE FROM projects_hist WHERE rowid NOT IN (SELECT rowid FROM (SELECT rowid, row_number() OVER (PARTITION BY id ORDER BY version DESC) rn FROM projects_hist) WHERE rn <= 2)"
```

- 2026-11-05 時点でこれを流すと 1,853 行 → 214 行、420MB → 約 56MB になる見込み。
- 「直近 2 版」の数を変えたいときは `rn <= 2` の数字を変える。

## 3. もう一度 1. を流して減ったことを確かめ、ツールの画面を再読み込みする

画面は未送信の内容をブラウザに残しているので、再読み込みすると自動で送り直す。右下が「保存しました」になれば完了。

## 補足

- 掃除しても保存が失敗し続けるときは、SQLite のファイルサイズが縮んでいない可能性がある（D1 は VACUUM を直接は流せない）。その場合は Workers 有料プラン（D1 10GB・CPU 30 秒）に上げるか、Claude に相談する。
- 根本対策（表紙画像を R2 に移す、履歴の保持数を減らす、履歴から画像を外す）は別タスク。
