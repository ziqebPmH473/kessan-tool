# DB保存 下準備：D1・R2 の作成と紐づけ、Cloudflare Access の設定

決算ツールの保存先をブラウザ（localStorage / IndexedDB）から Cloudflare に移し、別の端末からでも続きを作業できるようにするための、ダッシュボード側の準備です。
上から順にそのまま進めれば終わります。所要 15 分ほど。

- 本番URL: `https://kessan-tool-n9bqr59wv383lwpcyki3cnqhiktjzf0u6nxkcjlyq4kz8x.pages.dev/`
- Pages のプロジェクト名: `kessan-tool-n9bqr59wv383lwpcyki3cnqhiktjzf0u6nxkcjlyq4kz8x`（URL の前半と同じ）
  - 似た名前の旧プロジェクト `kt-c06fd74ea079` は使いません。
- コード側の割り当て名は **`DB`（D1）** と **`MEDIA`（R2）** に固定します。手順3の「変数名」は必ずこの2つ（大文字）。
- 設定が終わるまでは今までどおりブラウザ保存で動きます。壊れません。

---

## 1. D1 データベースを作る（文字のデータ用）

1. 開く: https://dash.cloudflare.com/?to=/:account/workers/d1
2. 「作成（Create Database）」を押す。
3. データベース名に次を入れる。
   ```
   kessan-tool
   ```
4. 場所（Location）はそのまま。「作成（Create）」を押す。
   - テーブルはツールが自動で作るので、SQL は入れなくてよいです。

## 2. R2 バケットを作る（音声・PDF・画像用）

1. 開く: https://dash.cloudflare.com/?to=/:account/r2
   - 初めて R2 を使うときだけ、支払い方法の登録を求められます。無料枠（10GB）内なら請求は 0 円です。
2. 「バケットを作成（Create bucket）」を押す。
3. バケット名に次を入れる。
   ```
   kessan-tool-media
   ```
4. 場所は「自動（Automatic）」のまま。「バケットを作成（Create bucket）」を押す。

## 3. Pages プロジェクトに紐づける

1. 開く: https://dash.cloudflare.com/?to=/:account/pages
2. `kessan-tool-n9bqr59wv383lwpcyki3cnqhiktjzf0u6nxkcjlyq4kz8x` を開く。
3. 上の「設定（Settings）」→ 左の「バインディング（Bindings）」を開く。
   - 見当たらない場合は「設定」→「関数（Functions）」の中にあります。
4. 「バインディングを追加（Add）」→「D1 データベース」を選ぶ。
   - 変数名: `DB`
   - D1 データベース: `kessan-tool`
   - 「保存（Save）」
5. もう一度「バインディングを追加」→「R2 バケット」を選ぶ。
   - 変数名: `MEDIA`
   - R2 バケット: `kessan-tool-media`
   - 「保存（Save）」
6. 紐づけは次のデプロイから効きます。「デプロイ（Deployments）」タブ → 一番上の「⋯」→「デプロイを再試行（Retry deployment）」を押す。
   - 押し忘れても、こちらが次に push すれば効きます。

## 4. Cloudflare Access でログインを掛ける（自分だけ入れるようにする）

Zero Trust（Access）は無料枠で使えます（50 人まで）。

1. 開く: https://one.dash.cloudflare.com/
   - 初めてのときは「チーム名」を決める画面が出ます。好きな名前でよいです（例: `sumikko`）。プランは「Free」を選ぶ。支払い方法の入力を求められたら無料プランのまま進めてください。
2. 左の「Access」→「アプリケーション（Applications）」→「アプリケーションを追加（Add an application）」。
3. 「セルフホスト（Self-hosted）」を選ぶ。
4. 次のように入れる。
   - アプリケーション名: `kessan-tool`
   - セッション期間（Session Duration）: `1 month`（いちばん長いもの。これで端末ごとに月1回のログインで済みます）
   - パブリックホスト名（Public hostname）→ 「ドメインを追加」でサブドメイン欄に本番のホスト名を入れる。
     ```
     kessan-tool-n9bqr59wv383lwpcyki3cnqhiktjzf0u6nxkcjlyq4kz8x.pages.dev
     ```
     - ドメインのプルダウンに `pages.dev` が出ない場合は、入力欄に上のホスト名を丸ごと貼ってください。
   - 「次へ（Next）」
5. ポリシーを作る。
   - ポリシー名: `me`
   - アクション: `許可（Allow）`
   - ルールの「含める（Include）」→ セレクター `メール（Emails）` → 値に自分の Google アカウントのメールアドレスを入れる。
   - 「次へ」→ そのまま「保存（Save）」。
6. ログイン方法はそのままで完了です。初期設定の「ワンタイム PIN」は、メールに届く 6 桁の数字を入れる方式です。端末ごとに月 1 回だけ求められます。
   - Google のボタン 1 つでログインしたい場合は、後述の「おまけ」を行います。あとからでも足せます。

### 注意（前に困ったところ）

- Pages プロジェクトの設定にある「アクセスポリシーを有効化（Enable access policy）」は**押さない**でください。あれはプレビュー用URL（`〜.pages.dev` の前に枝名がつくもの）専用で、本番には効きません。以前「テスト環境だけ入れない」となったのはこの機能です。
- Access を掛けると、ブラウザ以外からの `/api/〜` 呼び出し（GitHub Actions の定時実行など）も止まります。このツールにはそれが無いので問題ありません。
- ローカルの `wrangler pages dev` には Access は掛かりません。今までどおり動きます。

## おまけ：Google のボタンでログインする（任意）

1. Google Cloud で OAuth クライアントを作る: https://console.cloud.google.com/apis/credentials
   - 「認証情報を作成」→「OAuth クライアント ID」→ 種類「ウェブ アプリケーション」
   - 承認済みのリダイレクト URI に次を入れる（`<チーム名>` は手順4-1で決めた名前）。
     ```
     https://<チーム名>.cloudflareaccess.com/cdn-cgi/access/callback
     ```
   - できた「クライアント ID」と「クライアント シークレット」を控える。
2. Zero Trust の「設定（Settings）」→「認証（Authentication）」→「ログイン方法（Login methods）」→「新規追加（Add new）」→「Google」。
   - クライアント ID とシークレットを貼って「保存」。
3. 「Access」→「アプリケーション」→ `kessan-tool` → 「編集」→ ログイン方法で Google を選ぶ（ワンタイム PIN は外してもよい）。
