# 実装記録：「🎬 YT動画」タブ（テーマを問わない横動画）

作業日：2026-09-21 深夜（コミット `0846e02` 〜 `e390f41`、画面 v20260921-2333 より後）
対象：`index.html` のみ（`functions/` は変更なし）
設計書：[../design/2026-09-21_YT動画タブ.md](../design/2026-09-21_YT動画タブ.md)

## 目的

株価分析の横動画の仕組み（音声 → スライド → カット → ナレスラ → 投稿文）を、テーマを問わない動画（すみっこマネー大学の別テーマ）にも使えるようにする。

## 作りの要点

- **画面も関数も1組のまま、両方で使う。** 「🎬 YT動画」タブを開くと、株価分析の動画タブの中にある横動画のパネル（`#yt-root`）そのものを `#mode-yt` へ移して表示する（コピーではない）。右側（サムネイル／音声カット／ナレスラ／並べて表示）も `#capture-area-price` を共用。片方で直したことは、両方に効く。
- **違うのは保存先と、一部の文言だけ。** 動画の種類を `YT_CTX`（`stock`＝株価分析の横動画／`gen`＝YT動画）で持つ。
  - IndexedDB：`yaPut/yaGet/ynPut/ynGet` の中でキーを `ytKey()` に通す。株価分析の側は今までのキーのまま、YT動画の側は前に `gen:` を付ける。`tpl`（ナレスラのひな形）は共通。
  - 入力欄：作品ごとの欄（`ytWorkIds()`＝`YT_PERSIST_IDS` から `YT_SHARED_IDS` を除いたもの）を、切り替えのたびに `localStorage['kt-yt-fields-stock'|'-gen']` へしまい、相手側の値を欄に出す。いまの種類は `localStorage['kt-yt-ctx']`。
  - 切り替え（`ytSetCtx`）は「再生を止める → 保留中の保存を書き出す（`yaFlush`）→ 欄をしまう → 種類を変える → 欄と保存データを読み直す（`ytReloadAll`）」を、1つずつ順に行う（`_ytCtxChain`。連打しても順番に処理される）。
- **種類で分けた箇所**（ここを直すときは、もう片方にも同じ直しが要るかを確かめる）

| 箇所 | 株価分析の横動画 | YT動画 |
|---|---|---|
| 調査タブ | ①調査（レポート1〜2章から7章の動画資料） | テーマ・レポートの欄、①構成･出典（`ygStructPrompt`）、書き出し／読み込みのボタン |
| ファクトチェック `ytFactCheckPrompt` | レポート1〜2章は確認済みとして省く | 本文も確認の対象。構成の表も見る |
| 動画の意図 `ytIntent` | 銘柄名の株価○○の原因と強み… | 「テーマ」というテーマの動画 |
| 章の並び `ytChapters()` | `YT_CHAPTERS`（7章固定） | 動画資料の「## 構成」の表（`ytGenChapters`）。無ければ知らせる |
| スライド用 `ytSlideDesignerText()` | `YT_SLIDE_DESIGNER` そのまま | 同じ文面を土台に、銘柄・7章固定・noteの案内の箇所だけ置き換え。QRの段は、QR用のURLがあるときだけ |
| NotebookLM | 7章の決まった指示、銘柄名の読み（必須） | 貼った構成の章の順、読みがなは「言葉＝よみ、…」（無くてもよい） |
| 作品の名前 `ytWorkName()`／ファイル名 `ytFileBase()` | 銘柄名／コード_銘柄名 | テーマ |
| 割り当てのチャート | ティッカーは証券コードから | AIが ticker を出す（値動きの話が無ければ空） |
| note のURL `ytNoteUrl()` | 横の設定 → 記事タブ → 縦動画の設定 | 横の設定の欄だけ |
| 投稿文 | 読み替え（中段＝銘柄名、【#銘柄名（コード）】） | `ytPostRulesGen()`（中段＝この動画の主題。銘柄名の行・タグを付けない）。SNSの定型文の既定は `YT_SNS_FIXED_GEN` |
| 記事タブ | なし（株価分析の「記事・SNS」タブを使う） | note記事（無料・表なし・動画のURLを最初の段落のあと）とブログ記事（表あり） |
| 書き出し | 株価分析のタブごと（`hidden.yt`） | `TAB_IO.yt`（`hidden.yt`＋サムネイルの文言 `hidden.th`） |

- 出し分けは class で行う：`.yt-only-gen`／`.yt-only-stock`（`ytCtxApplyUi()`）。
- サムネイルの文言は3つの場面で別に持つ（note用／株価分析の横動画用／YT動画用＝`yg-th-text`・`yg-th-preset`）。
- 売買表現チェック `artComplianceCheck` は、第3引数でチェックする欄と結果の出し先を渡せるようにした（既定は今までどおり記事タブの4欄）。

## テスト・確認

ローカルの wrangler（`http://localhost:8799`）のブラウザ上で、仮データを入れて確認した。

- **株価分析の側のプロンプトは、変更前と1文字も変わらない**：段階④の前後で、①調査・②ファクト・スライド・NotebookLM・ソース・投稿文の材料・スライド名・ティッカー・noteのURLの出力を文字列で比べ、すべて一致。
- データが混ざらない：株の側に印を付ける → YT動画へ → 別の値を入れる → 戻る、で両方とも自分の値だけが出る。IndexedDB には `state`／`gen:state`、`srcedit`／`gen:srcedit` のように別々に入る。
- 保留中の保存：カットを変えた直後（保存の待ち時間の間）に切り替えても、元の側に保存される。連打しても最後の状態に落ち着く。
- リロード：YT動画を開いたままリロードすると、YT動画のタブと保存先に戻る。別のタブで開き直した場合は、保存先を株価分析の側へ戻す。
- 構成の表：3章の表を読み、スライドの枚数（章の数＋1）、スライド名、NotebookLM の章の順が一致。表が無いときは、やさしい文で知らせて落ちない。テーマ／レポートが空で①を押したときも同じ。
- QR：URLなしではスライド用プロンプトに QR の段が入らず、入れると入る。
- 投稿文：読み替えの段が1つだけ、X に銘柄名の行が付かない、Lemon8 の見出しに【#…】が付かない、SNSの定型文がYT動画用の既定で始まる（株の側は今までの文のまま）。
- 記事：3ブロックの読み取り、note の本文への動画URLの差し込み（2回押しても1か所）、禁止語の検知。
- エクスポート／インポート：YT動画で書き出し → 中身を消す → 株価分析を開いた状態から読み込み → YT動画のタブに切り替わり、同じ状態に戻る。株の側のデータは変わらない。
- 途中で見つけて直したもの：YT動画に入った直後の右側の表示の同期を `requestAnimationFrame` で待つと、裏のタブでは実行されず、サムネイルの文言の入れ替えが遅れた → その場で実行するようにした。

**確認できていないもの**
- Gemini API を使うボタン（ローカルに `GEMINI_API_KEY` が無い）：YT動画での割り当て（チャートの ticker）、投稿文、記事（作成と売買表現チェック）。本番で確認が要る。
- ChatGPT に「①構成･出典」とYT動画用のスライドのプロンプトを実際に投げた結果。文面は設計の方向どおりに入れただけで、出力を見ての調整はこれから。

## 判断事項

- 設計書では新しい部品のIDを `yg-` としていたが、`ytEl()`／`ytVal()`／`ytPaste()` をそのまま使うため、横動画の欄は `yt-g-*`（テーマ・レポート・番組の説明）、`yt-a-*`（記事）にした。`yg-` はサムネイルの文言の保存先（`yg-th-text`）と関数名（`ygStructPrompt` など）だけ。
- 設計書の「違うタブのファイルは止めて知らせる」は、今までの動き（確認のうえ、そのファイルのタブへ読み込む）に合わせた。読み込む先のタブを先に開き、保存先の切り替えを待ってから入れるので、相手側に入ることはない。
- ブログの YouTube は、ブログの管理画面の欄に URL を入れると記事の末尾に出る（`sumikko-money/docs/article-format.md`）。本文には入れず、URLをコピーするボタンだけ置いた。
- 記事の Gemini のモデルは、投稿文と同じ設定（`yt-m-post`）を使う。

## 残課題

1. 本番で、Gemini API を使うボタンの確認（上記）。
2. 実際のテーマで1本通し、①構成･出典・スライド・NotebookLM・投稿文・記事のプロンプトを、出力を見て直す。
3. スライド用プロンプトの置き換えは、株の側の文面（`YT_SLIDE_DESIGNER`）の文字列に頼っている。株の側の文面を直して置き換え元が無くなると、コンソールに `[yt] スライド用プロンプトの置き換え元がありません` と出る。そのときは `ytSlideDesignerText()` の置き換え元を合わせる。
4. YT動画のインポートで、ファイルにナレスラのひな形が無いと、共通のひな形が空になる（株価分析のインポートと同じ動き）。
5. YT動画を開いたままリロードしたあと株価分析へ移ると、株価分析のサブタブは「スライド作成」に戻る。

## 追記（2026-09-22）：調査の流れを作り直した

最初の実装は「レポートを貼る → ①で、レポートの本文に構成・出典の印・出典一覧を足したものをChatGPTに出し直させる → それをファクトチェック」だった。ユーザーの想定と違っていた（確認せずに進めたのが原因）。
「本文は書き換えない」とChatGPTに指示しても、出し直させる以上、元のレポートと同じかをツールで確かめられない。**レポートと、構成・出典は分ける**のが正しい。

いまの流れ（株価分析の「レポート（FC済み）＋動画資料（FC済み）」と同じ形）：

1. ChatGPTと調べて、レポートにまとめてもらう
2. ツールにテーマを入れ、レポートを貼る（`yt-g-report`）
3. レポートのファクトチェック（`ygReportFcPrompt`／③再CK／④修正＝全文を出させて貼り直す）
4. 「①構成」（`ygStructPrompt`）：FC済みのレポートから、**企画・構成の表・出典一覧だけ**を出させる。レポートの本文は出力させない
5. 結果を「3. 構成と出典」の欄（`yt-doc`）に貼る
6. 構成と出典のファクトチェック（`ytFactCheckPrompt` の YT動画側。レポートの中身は確認済みとして見ない）

- **レポートはプロンプトに入れず、「💾 添付ファイル」で保存した `レポート.md` を添付する**（長いレポートを貼るとChatGPTが固まる。ユーザー指摘）。3・4・6 のどれも同じ。
- 本文に［出典n］の印は付けない（レポートを出し直させないため）。代わりに、出典一覧に「裏づける記述」の列を足した（番号｜資料名｜URL｜ページ｜ページ内の位置｜裏づける記述｜表示用の出典表記）。`ytParseSources` は最後の列を表示用の表記として読むので、そのまま動く。
- 後工程（スライドの添付ZIP・NotebookLMのソース・投稿文・記事）の材料は `ygMaterial()`＝テーマ＋レポート＋企画と構成（出典一覧は除く）。
- 投資の軸は株価分析と同じ文のまま（話し手はアナリスト、視聴者は個人投資家、投資の内容をメインに）。YT動画は「投資に関する何かの話題」を解説する動画で、違いは話題だけ（ユーザー指摘）。
- ボタンの中に出し分け用の部品（span）を入れると、`copyText` がコピーのあと `textContent` で文字を戻すため、隠した分まで出て「①調査①構成…」になる。ボタンの文字は `ytCtxApplyUi()` で文字ごと入れ替える。
