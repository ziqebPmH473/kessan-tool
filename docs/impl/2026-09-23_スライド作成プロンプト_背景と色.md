## きっかけ

- ナレスラに入れた画像の文字が化けていた（「差」）。調べると、ツールは画像を元のファイルのまま持っていて（エクスポートの JSON も base64 で中身は同じ）、原因ではなかった。ChatGPT に「背景を薄く」と**直させたとき**に画像全体が描き直され、字が崩れていた。
- なので「直さずに1回で出せるプロンプト」にしたい、が出発点。

## 設定の持ち方

- 欄に id を付けない（id があると `TAB_IO.yt.roots` の中なので PJ ごとの行に入る）。`data-slide-color="base|head|font"`。
- 値は localStorage の `kt-slide-style`（JSON）。`assets/store.js` の `LS_SYNC` に入れたので、サーバーの shared の行に入り、全PJで共通。
- 初期値：基調色「白〜ごく淡いブルー、淡いグレー」、見出し「濃紺」（どちらも今までのプロンプトの色）、書体「ゴシック体」。
- プロンプトへは `ytSlideStyleApply()` で `{基調色}{見出し}{書体}` を置き換える。**欄が空ならその行ごと入れない**。

## 判断

- **青が強い理由**：最初のプロンプト（ChatGPT が株価分析のスライドを見て書いたもの）は「白を基調・青をメインアクセント・濃紺の見出し」。9/21 に Claude が背景を直すついでに「淡いブルー」を背景の基調に足し（bbe8819・4b91d50）、全体が青の資料になった。チャンネルは本来、白と黒ベース。
- **役割で色を決めない**：役割（強み・注意・補足）があると ChatGPT が要素ごとに色を判断してずれる（結論の「暴落の月というより〜」が注意の赤になった）。さらに、ナレスラに書き出す強調（赤・青・緑・黄）とスライドの色がぶつかり、強調が見えにくくなる。指示しなくても ChatGPT は強調の色を少し入れる（0533 で確認）。
- **設定は基調色・見出し・書体だけ**。欄は見出し付きで分ける（文字を消すと何の欄か分からなくなるため）。
- **ChatGPT の提案（表紙に「写真・都市・建物…は使わない」「抽象的な形・光・質感で」）は採らなかった**：禁止と例を書くと、前に無地にして物足りなくなった件・例が描かれる件と同じことが起きうる。許可を消すだけで様子を見る。

## 確認したこと

## 確認していないこと
