# 2026-09-25 保存の消失対策（画面に入れ終わった PJ だけ保存する／履歴）

## 起きたこと

2026-09-25 03:02・03:05（JST）に、株価分析の PJ 2件（ヨネックス ほか）が、株価分析の欄（銘柄名・レポート・記事など）を**画面の初期値**で上書きされた。横動画の欄はそのまま残っていた。

保存されていた中身は「ページを開き直したが、PJ の中身が画面に入らないまま」の状態そのもの。ツールは、PJ の中身を画面に入れられなくても（サーバーから読めない・途中でエラー）、タブが覚えている PJ の id に対して、閉じる・別タブに移るときに画面の中身を保存していた。

きっかけ（読み込みが失敗した理由）は記録が無く断定できない。03:00 の本番更新の直後に 2 つのタブを開き直した時間帯と一致する。

復旧は D1 の Time Travel で 02:55 の状態に巻き戻して書き出し → 元の地点へ戻し → 消えた欄だけをインポート用 JSON にして画面の「📥 インポート」で戻した（サーバーへの直接書き込みは、この作業環境の安全装置に止められたため）。

## 直したこと

### 1. 画面に入れ終わった PJ だけ保存する（assets/store.js, index.html）

- `S.loaded[kind]`：その kind で開いている PJ の中身を、このタブの画面に入れ終えた印。
- `saveState` は、id があるのに印が無い kind の行を送らない（`S.mode==='server'` のとき）。閉じる直前の保存（`flushOnHide`）は pending だけを送るので、同じく守られる。
- 印を付ける所：
  - 起動時：`readyInner` で行を読めた kind を `S.docOk` に記録し、`restoreState()` のあとに `KTStore.markLoaded()`（index.html の onload）。
  - PJ を開くとき：`ktOpen` で `tabIoApplyFields`・`ktKindAfterOpen` が終わってから `KTStore.markLoaded(kind,true)`。途中で失敗したら `markLoaded(kind,false)`（保存しない・札を赤にする・alert で知らせる）。
  - インポート：`importTabData` で欄を入れた直後に印を付ける（ユーザーの意思で置き換えるため）。
  - 新しい PJ の行を作るとき（`pidFor`／`saveState` の中）は印を付ける。
- `openProject` の先頭で印を消す。
- 右下の札に `notloaded`（赤「PJを読み込めませんでした。押して読み直す」）を追加。押すと開き直す。

### 2. サーバーに履歴を残す（functions/api/state.js）

- `projects_hist` テーブル（id, version, kind, title, json, meta, updated_at, saved_at。主キー id+version）。`ensure()` で自動作成（migrations 不要）。
- PUT で上書きするとき、上書き前の行を履歴に入れる（中身が同じ保存と `shared` は入れない）。1 id につき直近 30 版。
- DELETE で消す前にも履歴に入れる。
- 読む API：`GET /api/state?hist=<id>`（一覧）、`GET /api/state?hist=<id>&v=<version>`（1つ）。
- 画面から戻す機能はまだ無い（Notion に起票）。当面は wrangler か、上の API で json を取り出してインポート用 JSON にする。

## 確かめたこと（ローカル pages-db）

- `openProject` だけ呼んで印を付けない状態で欄を空にして保存 → サーバーの行は変わらない（version そのまま）。印を付けてから保存 → 書き込まれる。
- 開き直し → 印が付き、中身が残る。
- 2 回書き換え → `?hist=` に上書き前の版が 2 つ残る。
