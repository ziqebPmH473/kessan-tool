# DB保存 フェーズ1：保存の層を切り出し、D1・R2 に保存（2026-09-23）

Notion: 「DB保存 フェーズ1」。設計の相談は 2026-09-23 のチャット。下準備の手順は `docs/setup/2026-09-23_D1_R2_Access.md`。

## 何を作ったか

- `assets/store.js`（`KTStore`）：保存の層。入力内容とファイルの保存先を1か所にまとめた。
  - 入力内容：`saveStateNow()` が作る state を受け取り、localStorage（`kessanTool:v1`、今までどおり）に書いたうえで、
    種別ごとの行（`p:earnings` `p:stock` `p:price` `p:yt`）と `shared`（どの種別にも属さない欄・画面の状態・`kt-yt-ctx` などの小さな設定）に分けて `/api/state` に送る。
    送るのは変わった行だけ、900ms 後にまとめて。version が食い違ったら 409 が返り、画面の上に「別の端末の内容を読み込む／この端末の内容で上書き」の帯を出す。
  - ファイル：`KTStore.mediaNs(名前空間, 端末内の保存先)` で包む。端末内（IndexedDB、今までと同じ DB 名）に書きつつ、`/api/media/<ns>/<key>` にも送る（Blob は base64 にして JSON で）。読むときはサーバーを先に見る。
    名前空間：`files`（決算PDF・サムネ背景）`tts`（スライドごとの音声）`ya`（横動画のナレーション音声と作業状態）`yn`（スライド画像・割り当て・ひな形・素材）。控え（`kessanTool-ytHist`）は端末内だけのまま。
  - 起動 `ready()`：`window.onload` の最初で待つ。サーバーの内容を localStorage に写してから、今までの `restoreState()` が動く（復元の流れは変えていない）。
    サーバーが空なら初回として、この端末の内容（行とファイル全部）をまとめて送る。
    送れていない変更（`kt-sync-meta` の dirty）があって、サーバーも進んでいたら confirm で選ぶ。
  - 右下に小さな札：ブラウザに保存／サーバーに保存済み／保存中…／保存できませんでした／別の端末と食い違い／ログインが切れました（押すと開き直す）。
- `functions/api/state.js`：D1。`projects` テーブル（id, kind, title, json, version, created_at, updated_at）を初回に自動で作る。GET は全行、PUT は version を突き合わせて upsert。
- `functions/api/media/[[path]].js`：R2。GET/PUT/DELETE と、`?ns=` でキー一覧。
- `index.html`：IndexedDB の helper（`idbPut/idbGet` `vdDb*` `yaPut/yaGet` `ynPut/ynGet`）の中身を `KT_FILES` `KT_TTS` `KT_YA` `KT_YN` に差し替え。呼び出し側は触っていない。
  `window.onload` を `window._ktInitDone` の Promise で包み、`load` で動く後処理（関連記事の期間の初期化）はそれを待つ。
  `ktTabTitle(tab, fields)`：行の見出し（コード＋名前／テーマ）。フェーズ2の一覧で使う。
- `.claude/launch.json` に `pages-db`（`--d1=DB --r2=MEDIA` 付き、port 8798）を追加。ローカルでもサーバー保存を試せる。

## なぜそうしたか

- 画面の復元の流れ（`restoreState()` 以降）は複雑で触りたくなかったので、「起動時にサーバーの内容を localStorage に写す」だけにした。
- ファイルの端末内の DB 名を変えなかったのは、サーバー未接続のときに今までのデータがそのまま見えるようにするため。
- 行を種別ごとに分けたのは、フェーズ2（PJ一覧・切り替え）で行を増やすだけで済むように。ただし欄の所属は `TAB_IO` の roots で決めているので、横動画のパネル（`#yt-root`）のように開いているタブで親が変わる欄は、行の割り当てが動く。復元はすべての行を合わせて欄に入れるので今は問題ない。フェーズ2で決め直す。
- Access のログイン切れは fetch が転送されるので `redirect:'manual'` で見分けて、札を赤くする。

## 確かめたこと（ローカル wrangler、D1/R2 はローカル）

- 入力 → 約1秒後に PUT → 版が進む。ブラウザ側の保存を全部消して開き直す → サーバーの内容が戻る（欄・サムネ背景）。
- 別端末のふりでサーバーを進めてから編集 → 409 → 帯が出る → 「この端末の内容で上書き」で保存される。

## 本番で未確認

- 本番の D1/R2 での初回取り込み（PDF や音声が多いと取り込みに時間がかかる。札が「取り込み中…」の間は閉じない）。
- Access のログイン切れの札。

# フェーズ2a：PJ 単位のデータ（2026-09-23）

設計は `docs/design/2026-09-23_DB保存_フェーズ2_PJ一覧.md`。画面はまだ変えていない（内部だけ）。

- 行の id を `p:<kind>:<作成時刻>-<乱数>` に。フェーズ1の `p:earnings` などは起動時に見つけたら新しい id へ移す（新しい行を PUT → 古い行を DELETE。作成日時は古い行の created_at を引き継ぐ）。
- `meta` 列（{created, title, sub}）を足した（`ALTER TABLE` を try で。無ければ足す）。`GET ?list=1`（json 抜きの一覧、作成日の新しい順）と `GET ?id=a,b`、`DELETE ?id=` を追加。行ごとの `force`（shared はタブどうしで取り合うので最後に書いた方を採る）。
- ファイルのキーは `<pid>/<名前>`（R2 も IndexedDB も）。`mediaNs(ns, local, {kindOf, legacy})` で、どの PJ のものかを名前空間ごとに決める（横動画まわりは `ytGen()` で株価分析／YT動画を分ける。ナレスラのひな形 `tpl` は `_common`）。古いキー（pid 無し、`gen:` 付き）は起動時に移す（R2 は `POST /api/media?from&to`）。`ytKey` は `yaPut/yaGet/ynPut/ynGet` から外した（控えの `yh*` はそのまま）。
- タブごとの「開いている PJ」は sessionStorage `kt-cur`。新しいタブは今のところ「最後に開いた PJ」（shared.current）を開く（`OPEN_LAST_ON_NEW_TAB`。2b で空にする）。
- 空で開いた kind は、最初の保存を基準にして、そこから変わった時点で行を作る。ファイルを入れたとき（`pidFor(kind, true)`）も行を作る。
- 送れていない行は sessionStorage `kt-pending` に控え、同じタブのリロードで拾う（localStorage の state はタブどうしで上書きし合うので使わない）。
- 2b の画面から使うもの：`KTStore.listProjects(kind)` `openProject(kind, id)` `deleteProject(id)` `refreshRows()` `cur` `setSub(kind, sub)`。
- ローカルで確認：フェーズ1の行と R2 のキーが新しい形へ移る／空で開いて入力すると行ができる／一覧が作成日順に出る。

# フェーズ2b：上の1行（種別 ＞ PJ）と PJ の切り替え（2026-09-23）

- 上の4タブを、`種別 ▼`・`PJ ▼（作成日 時刻 名前）`・`＋新規`・`削除` の1行（`.mode-tabs.kt-pjbar`。sticky と `ktStickyTops` はそのまま効く）に置き換えた。`switchMode()` は残し、開いている種別を sessionStorage `kt-mode` に覚える。
- 新しいタブは決算・空で始まる（`OPEN_LAST_ON_NEW_TAB=false`）。同じタブの開き直しは同じ PJ。横動画の種類（`YT_CTX`）も `kt-mode` から決める。
- `ktOpen(kind, id)`：いまの内容を保存して送り切る（`KTStore.suspended` で切り替え中は行に写さない）→ `openProject` → `switchMode` → 欄を組み立て直後の値に戻す（`ktResetKindFields`。横動画の欄は `YT_FIELD_DEFAULTS`）→ 行の欄を入れる（`tabIoApplyFields`）→ 種別ごとの描き直し（`ktKindAfterOpen`。起動時の後半と同じこと）→ ファイルを読み直す（`ktKindReload`：PDF・音声・サムネ背景・横動画一式）。
- 横動画の種類の切り替え `ytSetCtx` から、欄の入れ替え（localStorage `kt-yt-fields-*`）を外した。欄は PJ の行から入る。起動時に欄へ入れる順は「開いている種別の行を最後」（横動画の欄は株価分析と YT動画で同じ id なので）。
- 削除は自前のモーダル（`ktModal`）で確認してから `KTStore.deleteProject`（行と、その PJ のファイルを R2・端末内とも消す）。
- 一覧は `KTStore.listProjects(kind)`（作成日時の新しい順）。プルダウンを触ったとき（focus）と保存で見出しが変わったとき（`KTStore.onChange`）に出し直す。
- ローカルで確認：PJ の切り替えで欄が入れ替わる／種別を変えると空／入力すると一覧に入る／削除のモーダル→消える／YT動画↔株価で yt-root の移動と音声の読み直し／新しいタブは決算・空。
- 幅が狭いと「削除」が2行目に落ちる。1行のままか上下2段にするかは見てから決める（設計書のとおり）。
