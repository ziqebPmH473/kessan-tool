## 目的

株価分析の「動画」タブの横（YouTube）で、調査 → 音声 → スライド → カット → ナレスラ（.svpz）→ 投稿文 までを通せるようにする。
題材は中外製薬（4519）。実際に1本作りながら、詰まった箇所を直した。

## 現在の画面構成

内側タブ：**調査／音声／スライド／カット／ナレスラ／投稿文／設定**（リロードしても開いていたタブに戻る。sessionStorage）

| タブ | 中身 |
|---|---|
| 調査 | ①調査 ②ファクト ③再CK ④修正 のプロンプト、動画資料の貼り付け（貼ると②を自動でコピー）、🔗 出典のリンクを確認 |
| 音声 | 1. NotebookLM（読みがな・今回のテーマ・ソース.md・指示）／2. 音声の読み込み・文字起こし（Groq Whisper）・Gemini文字起こしとの突き合わせ |
| スライド | 1. ChatGPT用プロンプト＋添付ZIP／2. 直してもらう（チェック17項目＋手入力）／3. できたスライドを取り込む（読み込み・まとまりの読み取り・まとめスライドのQR） |
| カット | 1. 削る箇所の判定（プロンプト／Gemini API／貼り付け）／2. カット後の音声 |
| ナレスラ | 1. 演出の割り当て／2. 出典の画像／3. ナレスラのプロジェクト（.svpz） |
| 投稿文 | タイトル3案・サムネ3案（1案ずつコピー、サムネに入れる）・概要欄とX（貼れる全文） |
| 設定 | QR用URL（いま使うURLを表示）・チャート期間・試聴の前後・NotebookLMの長さ・概要欄の定型文 |

右ペイン：横動画のときは **サムネイル／音声カット／ナレスラ／↔ 並べて表示**（既定は並べて表示。左＝ナレスラ、右＝文の一覧）。スライド作成・記事・縦（SNS）では音声カット・ナレスラを出さない。

## 実装内容（主なもの）

### タブと不要コードの整理
- タブを作る順に並べ替え。ツールのHTMLで横スライドを作る仕組み（JSONプロンプト・組み立て・`.yt-s` のCSS・右ペイン）は削除（戻すなら `bee088a`）。

### 調査
- ファクトチェックから、レポート1〜2章の本文を外した（確認済みの内容まで見に行って時間がかかるため）。
- 出典のURLを、AIに任せずツールで確認：`/api/grab?check=1`（開けるか・種類だけ返す）。結果（開けないURL、PDFのはずなのにページになっている出典）を②ファクトのプロンプトに差し込む。FCでは全URLを1件ずつ開くことを必須にした。
- 調査プロンプト：元がPDFの資料は、PDFのURLとページ番号を書かせる。

### スライド（ChatGPTの画像生成）
プロンプト `YT_SLIDE_DESIGNER` は、ユーザーの文面を土台に、実際の出力を見ながら直した。現在の章立て：
最終目的（投資判断の材料）／**内容の基本原則（レポートが本体、音声は順番・強弱・表現の調整材料）**／枚数と表紙の役割／設計思想／情報量／1枚としての完成度（章ごとに主役の見せ方を1つ決める。固定レイアウトにしない）／ズーム／音声・レポートとの整合性／チャート／まとめの追加要件（QR用の空き正方形）／背景／デザイン／作成手順／出力形式（画像で、全8枚）／内部指示の扱い／表示してはいけない情報／表示するもの。

経緯で分かったこと：
- 出力形式を書かないと .pptx で返ってくる。「1枚ずつ確認」と「8枚」を同時に書くと1枚で止まる。
- 企画方針の文を素で渡すと、表紙のサブコピーとして描かれる → 入力1を【内部用の企画方針】の箇条書きにし、シリーズ名は渡さない。
- 章の「扱う内容」の文が、そのままラベルとして描かれることがある（「ここまでの要点」）→ 文言を変え、区分ラベルを禁止。
- 見出しは固定タイトルをやめ、章の「扱う内容」を渡して、音声とレポートから付けさせる。
- 参考画像（note用スライド）は渡さない（レイアウトと中身まで引っ張られる）。
- **背景**：禁止を強めると（無地・装飾なし）、リッチさ（奥行き・質感）まで落ちた。現在は「本文の背後だけ静かに、装飾は余白側、強くぼかして白に寄せる。表紙は写真可」。
- 「許可の一文」を書くと必ず使ってくる（余白のモチーフ、他社名など）。不要な許可は書かない。

### カット
- 判定プロンプト：相槌だけ・感嘆だけ・復唱・合いの手を1点の対象に明記。締めの「本日はここまでです」は自動で削る（NotebookLMの指示では残す。最後の単語が切れるのを防ぐための文）。
- 一覧：点数を数字ではなく言葉と色で（不要／脇道／補足／重要／必須）。行のハサミボタンは削除（ドラッグで選ぶ→そばのボタン、で完結）。
- 切り口の不具合を修正：
  - 短い相槌で、始点と終点が同じ無音に吸着して長さが潰れ「位置を計算できませんでした」になる → 吸着なしの時刻 → 文の時刻、の順に逃がす。
  - 終点が、次に残す文の頭（「あの、」）を越えて先の無音まで飛ぶ → 吸着先との間に声があれば飛ばない（`yaSnapOnsetEnd`）。
  - AI判定の部分カットは、表記が違っても一番近い場所を探し、それでも無ければ文頭のおおよその範囲で作る（一覧に「一部≈」）。
- 書き出す字幕：終わりが始まりより前／前後と重なるものを直す（相槌が重なる箇所で起きていた）。

### ナレスラ（演出の割り当て）
- 時刻と長さは**カット後**で扱う（プロンプトの各文、3秒未満の判定、右ペインの表示）。.svpz の時刻は元の音声の時刻（ナレスラの仕様）。
- スライドは**音声で出てくる順**に並べる（音声が「強み→急落の真相」の順なら、その順で表示・書き出し）。スライド1は必ず先頭の文から。近くに章の切れ目があれば切替を寄せる。
- 出典の件数は長さに比例（カット後1分あたり約0.8件、1〜10件、1件5〜8秒、20秒以上あける）。チャートは別枠で、ティッカー・足・期間をAIに出させる。出典・チャートを出している間はズームも強調も外す。
- 右ペインの行：**種類（色つきの選択欄）→ 枠 → 文番号（始まり〜終わり）→ 話している文 → 消す**。枠は `2+3` と書ける。入れ子の枠は外側だけにまとめる。「＋ 追加」は見出しの左、押したときだけ入力行。「文」ボタンで右の一覧がその文へ。
- 文の一覧の帯は1種類：割り当て後は「■ スライドn／テロップ／n〜m文／元→カット後」（押すと左のスライドへ、▲▼で切替を1文ずつ動かす）。

### 出典の画像
- `/api/grab`：PDFと画像だけを通す中継。PDFは pdf.js（`intent:'print'`）で指定ページを描き、ドラッグで範囲を切り抜く。元画像と範囲を残すので選び直せる。
- 出典一覧の読み取り：番号が「出典1」でも読む／1つの欄の複数URLを全部持ち、PDFを優先（●○で選び直し）／「ページ内の位置」も読み、行と切り抜き画面に「撮る場所」を出す。
- 種類（資料／チャート）：株価・指数系は自動でチャート。チャートは TradingView のリンク（`&interval=` 付き）、画像だけ差し込み、動画上の表記は付けない。
- 使われていない出典は薄く表示・取得させない。画像なしは赤、ありは緑。上に集計。まとめて取得（未取得・使用中・資料のみ）。
- キャプチャは、行を選んで Ctrl+V（または「貼り付け」）。ボタンは言葉に。
- 出典の表記の位置：左下・左詰め（X 0.0096 / Y 0.97 / align left / 線3）。ユーザーがナレスラで直した値に合わせた。
- まとめスライドのQR：ChatGPTに空の正方形を描かせ、ツールはQRのドットだけを貼る（地の色と濃い色は画像から拾う）。URLは 横の設定 → 記事タブの記事URL → 縦動画の設定 の順。

### 投稿文
- ルールは Gem の原文をそのまま使い、読み替えだけ末尾に足す（シリーズ名、サムネは `上段：銘柄名：下段`＋色マーカー `*オレンジ* #水色# %黄色%`、付帯文はツールが付ける）。
- 概要欄＝本文 → noteの記事リンク → 定型文（使用ツール・AI注意書き）→ ハッシュタグ。X＝`【#銘柄名（コード）】` → YouTubeのURL → 本文 → ハッシュタグ。どちらも欄に全文を出す。

## 判断事項

- kessan-tool 側の割り当て・手直しUIは**本実装として作り込む**（ユーザー方針）。ナレスラへの展開は将来の上位プラン構想で、別に考える。
- 青（章）と黄（スライド）の帯を分けたのは不要だった → 1種類に。
- 原因を追う変更と、別件の指示は、コミットを分ける（混ぜると、どの変更が効いたか分からなくなった）。
- プロンプトは、悪化したら「足す」より先に「原因になった変更を戻す」。

## 追記（2026-09-21 午後）

### エクスポート／インポートに横動画のデータを入れた
- 株価分析の 📤エクスポート（JSON）の `hidden.yt` に、音声ファイル・文字起こしの時刻とカット・スライド画像（まとまり、QRを貼る前の元画像と位置）・演出の割り当て・ナレスラのひな形・出典の画像（切り抜き前の元画像と範囲）・出典の手直し・リンク確認の結果を入れる。画像と音声は data URL（base64）。
- 📥インポートは、ファイルに `hidden.yt` があれば IndexedDB（`kessanTool-ytAudio`／`kessanTool-ytNare`）を書き換えて読み直す。無いファイル（古い書き出し・自動の書き出し）なら、いまの横動画データには触らない。
- 記事を生成したあとの自動エクスポートは、軽い形（`{light:true}`。横動画の重いデータなし）のまま。全部入りは、手で 📤 を押したとき。
- 音声が入るので、ファイルは音声の約1.3倍＋画像の分の大きさになる（5分半の m4a で約15MB）。
- 確認：仮のスライド・割り当て・出典画像と実音声で、書き出し → IndexedDB を全部消す → 読み込み → 同じ状態に戻ることをローカルで確認。

### サムネイルの文言を、note用と YouTube用で別に持つ
- 入力欄（`th-input`）は1つのまま。横動画（株価分析＞動画＞横）に入る／出るときに中身を入れ替える（`thCtxSync`）。保存先は `th-note-text`／`yt-th-text`、型（note／YouTube）も `th-note-preset`／`yt-th-preset` で別に持つ。いまどちらかは `th-ctx`。
- YouTube用がまだ空のときだけ、note用の文言を出発点として見せる。以後はどちらを直しても、もう片方は変わらない。リロード・エクスポート／インポートでも両方残る。
- 横動画のときは、入力欄の上に「YouTube用のサムネイル（note用とは別に保存されます）」と出す。
- 背景画像・透過率・拡大率は共通のまま（分けていない）。
