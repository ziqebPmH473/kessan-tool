# 実装記録：note記事への関連記事リンク（あわせて読みたい）

作業日：2026-09-18
対象：`index.html`、`functions/api/note-articles.js`（新規）

## 目的

株価分析のnote記事の末尾に、過去記事へのリンクを自動で差し込む。URL・どの記事を選ぶか・紹介文の3つをツール側で埋め、ユーザーはnoteに貼ってEnterを押すだけにする。

## noteの仕様（調査結果）

- ユーザー提供リンクの「embed機能 開発ガイドライン」は**外部サービス提供者が自社サービスをnoteに埋め込むための申請手順**で、今回の用途とは無関係。個人運営者は申請不可と明記されている。
- 記事カードには `^7201`（株価チャート）のような専用記法は**ない**。URLを単独の段落に置くだけ。
- ヘルプ「テキスト記事に埋め込みできるサービス一覧」に「note記事」があり、URL貼り付けでカード化される。一覧外のURLは貼り付け後にEnterが必要。
- **ユーザー実機確認**：本文をまとめて貼るとURLは文字列のままだが、**URL行の末尾にカーソルを置いてEnterを押すとカード化される**（`^7201` と同じ挙動）。これを前提に、本文へURLを直接埋め込む設計にした。
- 参考：株価チャートの記法は日本株 `^証券コード` / 米国株 `$ティッカー`、期間6か月固定、ETF・REIT・投信・指数は非対応。ユーザーは既に利用中。

## 実装内容

### 1. `functions/api/note-articles.js`（新規）

- note の公開API `https://note.com/api/v2/creators/{urlname}/contents?kind=note&page=N` を中継する。ブラウザから直接叩くとCORSで弾かれるため。
- 取得項目：タイトル（name）、URL（noteUrl）、公開日（publishAt）、価格（price）、ハッシュタグ（hashtags、`#`を外して保持）。**タグに証券コードが必ず入っている**ため銘柄の紐付けに使える。
- パラメータ：`urlname`、`days`（既定90）、`paid`（既定1＝有料のみ）。
- **subrequests対策**：全記事は144本（24ページ）あるが、指定期間より古い記事が出た時点で打ち切り、さらに `PAGE_MAX=12` で上限を設ける。Cloudflare無料プランの「1実行50 subrequests」に引っかからないようにする（[[affiri-console-subrequests]] と同じ制約）。

### 2. 関連記事の選択・挿入（`index.html`）

- UI：ハッシュタグ欄の下に「関連記事」のセレクト（候補一覧）、🔄（一覧の再取得）、紹介文の入力欄、「📎 本文に挿入」ボタン、設定（note ID／直近N日）。
- 候補は localStorage（`kt-note-articles`）にキャッシュし、6時間で更新。リロード時はキャッシュから復元する。
- **スコア**：同一証券コード +25 ／ テーマタグの一致 各+10 ／ 新しさ 最大+9。同点は公開日の新しい順。
- **汎用タグの除外**（`REL_STOP_TAGS`）：株価分析・株式投資・日本株など、どの記事にも付くタグはテーマ一致に数えない。これを入れないと汎用タグだけで並び順が決まってしまう（テストでユニオンツールがディスコより上に来た）。
- **自分自身の除外**：URL一致、タイトル一致に加え、「同一証券コードかつ公開から14日以内」を今回の記事とみなして除外する。同一銘柄でも14日より前なら過去の分析としてリンク対象に残す。
- **紹介文**：Gemini の Lite 系（`cls:'low'`）に1回だけ投げ、40〜70文字の1文を書かせる。売買行動・読者への行動要求の禁止も指示に含める。失敗時はタイトルからのテンプレートに落とす。
- **挿入位置**：本文の末尾（「ご注意」画像の後）。`## あわせて読みたい` + 空行 + 紹介文 + 空行 + URL + 改行。URLを単独段落にするため前後に空行を入れる。
- **再挿入**：`## あわせて読みたい` 以降を削って付け直すので、何度押しても増えない。
- 記事生成（`geminiArticle`）の最後に自動実行（生成 → 売買表現チェック → 関連記事 → 自動エクスポート）。失敗しても記事は残す。

## 判断事項

- **本数は1本**。noteのカードは横幅いっぱいで縦に積まれるため、複数だと本文を分断する。note自身が記事下部に「人気記事」を出しているので重複感もある（ユーザー指摘）。
- **位置は本文の末尾**。無料部分（導入直後・1章直後）に置くと離脱と競合する。特に1章直後は有料ラインの直前で、購入判断の瞬間に出口を見せることになる。末尾なら到達するのは読み終えた人だけで、購入済み＝次も買う見込みが高い相手に当たる。無料読者への回遊導線はnoteの「人気記事」が担う。
- **画像との連続を避ける**：当初案の「まとめ画像とご注意画像の間」は画像→カード→画像で詰まる（ユーザー指摘）。ご注意画像の後ろに移し、見出しと紹介文をクッションにした。プロンプトの「画像2枚を連続して出す」指示も壊さずに済む。
- **有料記事のみ・直近90日**。ユーザー指示（株価分析の記事は有料、古い記事は避けたい）。90日で29本の候補が出る。
- 紹介文は上位モデルの1日20回枠を使わないよう Lite 固定。

## テスト・動作確認

- `node --check`：`index.html` のインラインJS 2ブロック、`note-articles.js` とも pass。
- ローカルプレビュー（wrangler pages dev）で確認：
  - `/api/note-articles?urlname=sumikko_money&days=90&paid=1` → 有料29件、タグに証券コードあり。
  - 自動選択：タグ `#半導体製造装置 #AIサーバー` で**ディスコ**（2タグ一致）が1位。汎用タグ除外の修正前はユニオンツール（1タグ＋新しさ）が1位だった。
  - セレクトから別の記事に変更 → 紹介文が作り直され、本文のブロックが差し替わる。見出しの重複なし。
  - 本文末尾の空行が3つにならない（`relStrip` が常に末尾の空白を落とす）。
  - 証券コード6920（12日前に公開）を今回の銘柄にすると、その記事が候補から消える。
  - Gemini はモック応答で確認。
- **未確認**：実Geminiでの紹介文の品質、note上でのカード化（ユーザー側で確認済みの挙動に依存）。

## 追加修正（同日）：並び順と件数

初版はセレクトをスコア順で並べ、対象を直近90日（29件）にしていた。ユーザーから「件数が少ない」「並び順が日付の降順でないのが気になる」と指摘され修正。

- **一覧は公開日の降順**に固定。自動選択はスコア順のままで、**スコア上位3件に⭐**を付けて目印にした（探すのは日付順、おすすめは記号で分かる形）。
- **対象期間の既定を90日→365日**に拡大。有料記事85件（最古 2025-10-04）が候補になる。`PAGE_MAX` を 12→26 に引き上げ。全144本＝24ページでも subrequests は24で、無料プランの上限50に収まる。取得は約2.9秒で、6時間キャッシュされる。
- **新しさの配点**を `max(0,9-日数/10)`（90日で0）から `max(0,12-日数/30)`（1年で0）に変更。期間を広げても直近が選ばれやすいままにする。
- **保存済み設定の移行**：既存ブラウザには90が保存されているため、`kt-rel-days-365` フラグで1度だけ365に引き上げ、旧期間のキャッシュを捨てる。`restoreState`（`window.onload` 内）より後に動かす必要があるので `window.addEventListener('load')` で実行する（`document.fonts.ready` に置いた初版は復元で上書きされ効かなかった）。
- 確認：365日で85件、日付降順、⭐が上位3件（ユニオンツール・ディスコ・レーザーテック）に付くこと、移行後に設定欄が365になることをローカルで確認。

## 残課題・次回

- 本番で1本生成し、選ばれる記事と紹介文が妥当か確認する。
- 候補の絞り込み（期間90日・有料のみ）が厳しすぎる／緩すぎる場合は設定欄で調整する。
- 売買表現チェックは紹介文を対象にしていない（本文に挿入された後は本文の一部になるため、次回チェック時には対象になる）。生成フローではチェックの後に挿入しているので、紹介文だけはAIチェックを通っていない。気になるなら挿入をチェックの前に移す。
- 候補が85件あるため、セレクトから手で探すのが大変なら絞り込み（銘柄名の検索など）を足す。
