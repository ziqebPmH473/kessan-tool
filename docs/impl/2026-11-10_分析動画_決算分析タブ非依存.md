# 分析動画を、決算分析タブの「2.」の欄に頼らず作れるようにする（2026-11-10）

## きっかけ

分析動画だけを使うとき、決算分析タブ（1枚画像）のスライド用データ「2.」を作ってファクトチェックを繰り返す意味がない（すみぽん）。
調べると、動画の本体（業績の数字・評価）は PDF から別に抽出した動画用 JSON で作られていたが、次の4つは「2.」から借りていた。

| 値 | 以前の出どころ | 直したあと |
|---|---|---|
| 株価の推移・決算前後の株価・変化率 | 「2.」の CHART_DATA・MARKET_REACTION（無ければ自動取得） | 株探の自動取得（`_earnFetched`）が先。無い項目だけ「2.」 |
| 発表日（チャートの発表日の位置） | 「2.」の HEADER.announcement_date（無ければ基本情報の欄） | 基本情報の「発表日」が先 |
| 業績予想の比較（予想スライド） | 「2.」の GUIDANCE だけ | 「2.」に無ければ動画用 JSON の forecast から作る |
| 今期の評価ラベル（サムネの上段） | 「2.」の HEADER.result_label | 「2.」に無ければ動画用 JSON の result_label |

株価を「2.」から拾っていたのは、1枚画像の流れ（AI が自動取得の値を「2.」に写す）の上に分析動画を載せた経緯によるもの。自動取得の値は PJ の保存データにも入っているので、直接使うほうが正確。

## 変更（visualizer c52595b → kessan-tool 403e8fa）

### 部品（kessan-visualizer）

- `src/schema/common.ts` ForecastSchema に `revision`（unchanged／up／down／new）・`previous`（修正前の売上高・営業利益・純利益・配当）・`revision_reason` を足す。
- `src/schema/analysis.ts` トップに `result_label` を足す。`src/schema/visualization.ts` summary に `result_label`。
- `src/analysis/extras.ts` `forecastRevisionFromInput()`：forecast と今期の実績から「2.」の forecast_revision と同じ形を作る。
  - 本決算（FY）：左＝今期実績、右＝来期予想、率＝前年比、進捗率なし
  - 修正あり：左＝修正前、右＝修正後、率＝修正率、進捗率＝今期ここまでの実績 ÷ 修正後、理由＝revision_reason
  - 据え置き・新規：左右同じ値（画面は1本の棒）、進捗率＝実績 ÷ 通期予想
  - 修正の向きが無いときは営業利益（無ければ売上高）の前後から決める
- `src/analysis/build.ts`・`src/embed/index.tsx`：forecast_revision の行が無ければ上で作る。embed に `KessanViz.forecastRevision` を公開。
- `src/analysis/prompt.ts`：forecast の修正状況・修正前・理由と result_label の決まりを足す（1枚画像のルール6・7を移した）。
- `src/analysis/normalize.ts`：日本語の修正状況（据え置き・上方修正…）も読む。

### ツール（index.html）

- `evVizExtras()`：自動取得 → 「2.」の順。発表日は基本情報の欄 → 「2.」。「2.」が無くても返す。
- `evVizThumbText()`：評価ラベルと修正の種類を、「2.」に無ければ動画データ（summary.result_label・forecast_compare.status）から。
- 分析動画を開いたときのサムネ自動入力を、「2.」が無く動画データだけでも走らせる。
- 「✏ データを直す」の予想欄のもとを、「2.」に無ければ `KV.forecastRevision(analysis)` から。
