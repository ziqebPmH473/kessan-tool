# 2026-11-05 保存データの軽量化（表紙画像を R2 へ、履歴を減らす）

## きっかけ

本番の D1（kessan-tool）が無料プランの上限 500MB にほぼ達し（499.68MB）、保存（PUT /api/state）が CPU 上限超過の 503 と、その後 500 で失敗し続けた。
内訳は現在の PJ 90 件で 28MB、履歴 projects_hist 1,853 行で 420MB。決算 PJ 1 件が約 525KB で、そのうち約 420KB が分析動画の表紙画像 2 枚（`ev-viz-settings` の `cover_image_landscape` / `cover_image_portrait`、base64 JPEG）だった。
応急処置は履歴を PJ ごとに直近 2 版に削った（`docs/setup/D1_履歴の掃除.md`。499.68MB → 93.6MB）。

## 直したこと（3 コミット）

1. **履歴**（`functions/api/state.js`、489fd2e）
   - `HIST_KEEP` 30 → 5。
   - 履歴に入れる json から `data:image/…;base64,` の 200 文字以上を `data:,hist-omitted` に置き換える（`histSlim`）。履歴から戻した PJ は表紙を作り直す。
   - D1 のエラー文を画面向けの日本語に（`dbErrorText`：満杯／大きすぎ）。
2. **表紙画像を R2 へ**（`index.html`、f2c10b6）
   - 設定 JSON には目印 `kt-file:ev:cover:h`／`kt-file:ev:cover:v` だけ残し、画像は `KT_FILES`（ns `files`、キー `ev:cover:h`／`v`、PJ ごと）に置く。`KT_FILES` の `kindOf` に `ev:` 始まり → `earnings` を追加。
   - 部品（KessanViz）は data URL しか知らないので、`evVizMount` で渡す直前に `evCoverLoad` で戻し、部品の `onChange` と `evThApply` は `evVizSettingsWrite` → `evCoverStore` で目印に戻してから欄に入れる（1 列に並べて順番を守る）。
   - 古い PJ（JSON に base64 が入ったもの）は、開いて `evVizMount` が走ったときにファイルへ移して保存し直す。
   - 表紙を null にしたらファイルも消す。読み戻しはメモリ → 端末内（IndexedDB） → R2 の順。
3. **保存失敗の理由を札に**（`assets/store.js`、ff69c25）
   - `setStatus('error', msg)` の msg を札の文に出す（70 文字で切る、全文は title）。`HTTP 5xx` には「サーバーが応答できませんでした」を添える。通信そのものの失敗も理由を渡す。

## 確認（ローカル wrangler pages dev、D1・R2 つき）

本番から取った住友化学（4005）の PJ の `ev-viz-json`・`ev-viz-settings` を入れて確認。

| 項目 | 結果 |
|---|---|
| `ev-viz-settings` の大きさ | 424,757 → 3,103 文字 |
| 保存（PUT /api/state）の送信 | 42,027 バイト（目標 100KB 未満） |
| R2 への表紙の送信 | `files/<pid>/ev:cover:h`・`v` に PUT 200、読み戻しは 304 |
| 部品への表示 | サムネの場面を有効にすると縦の表紙（195KB の JPEG）が出る。設定 JSON は目印のまま |
| 履歴 | base64 入りで保存した版を上書きすると、履歴の json は 41,906 バイト・`hist-omitted` 2 か所・base64 なし |
| 札 | 503 → 「保存できませんでした：HTTP 503（サーバーが応答できませんでした…）」、DB 満杯の文もそのまま出る。復旧後「サーバーに保存済み」 |

## 残り

- 本番で古い PJ を開いたときの移行（JSON が軽くなる）は未確認。開いた PJ から順に軽くなる。開いていない PJ は大きいまま（合計 28MB なので急がない）。
- 決算まとめ（digest）はほかの PJ の表紙を使っていないので影響なし。
