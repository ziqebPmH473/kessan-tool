# 実装記録：株価分析の記事に「公開した」ボタン（公開日・週何本目・この週の本数）

作業日：2026-10-14
対象：`index.html`（株価分析タブ ＞ 記事・SNS ＞ ハッシュタグの下）、`assets/store.js`
Notion：決算ツールPJタスク「株価分析の記事に「公開した」ボタンを置き、公開日・週何本目・今週の本数を出す」

## 目的

note のメンバーシップ（分析記事 週1本／週2本／読み放題）に合わせ、週の何本目かで公開範囲を変える運用になった。
記事を公開したら「公開した」を押すだけで、公開日・その週の何本目か・その週に何本公開したかが分かるようにする。

## 決めたこと（ユーザー指示）

- 公開日＝「公開した」ボタンを押した日（note から取らない）。
- 週は月曜〜日曜。数えるのは有料記事だけで、株価分析に限らない。
- 「何本登録されているか」＝ツールで公開日を入れた本数。
- 置き場所はハッシュタグの下。表示だけで、公開範囲の切り替えは note 側で手で行う。

## 作り

- 公開日は2か所に持つ。
  - PJ の json：隠したテキスト欄 `art-pub`（PERSIST_IDS に追加）。PJ を開き直すと欄に戻る。
  - PJ 一覧の meta：`meta.published`（`assets/store.js` の `metaOf`）。一覧（`/api/state?list=1`）だけで全 PJ を数えられる。
- `KTStore.setPublished(kind, iso)`：meta に公開日を入れる。欄が変わっていなくて行が作られないときは、最後に送った json のまま meta だけ変えて送り直す（`setSub` は json が同じだと送られない作りだったので、そこを補った）。
- 数える側（`artPubList`）は `KTStore.rows` の全種類を対象にし、同じ週（月曜 0:00 基準）の `meta.published` を公開日順に並べる。自分の PJ が一覧にまだ無いとき（送信前）は、自分より前の本数＋1 で出す。
- 表示（`artPubRender`）：
  - 押す前：「まだ公開していません。いま公開すると 10/12〜10/18の週の N本目（この週の公開 M本）」
  - 押した後：「公開日 2026/10/14：10/12〜10/18の週の N本目（この週の公開 M本）」＋「取り消す」
  - マウスを乗せると、その週の PJ のタイトルを本数順に出す。
- `ktPjFill`（PJ を開いたとき・一覧を取り直したとき）の最後で描き直す。

## はまったこと

- `<input type="hidden">` は `.value` を入れると value 属性（初期値）ごと書き換わるため、PJ 切り替えのリセット（`el.value=el.defaultValue||''`）が効かず、前の PJ の公開日が次の PJ に残った。`type="text"` を `display:none` で隠す形に変えた。
  - 既存の `art-rel-url`（hidden）も同じ性質を持つ。いまは記事生成のたびに上書きされるので表に出ていないが、同じ症状が出たらここを疑う。
- 株価分析タブの kind は `price`（`stock` は個別銘柄分析）。最初 `stock` で書いていた。

## 確認（ローカル wrangler pages dev、D1/R2 付き）

- 公開 → 一覧の meta に published が入り、「1本目（この週の公開 1本）」。別の PJ で公開 → 「2本目（2本）」。
- 新規 PJ を開くと欄が空で「いま公開すると 3本目」。取り消す → meta が空に戻り、ほかの PJ の本数が減る。
- `node --check`：index.html の script 2本、store.js とも pass。
