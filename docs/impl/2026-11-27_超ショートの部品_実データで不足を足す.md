## やったこと

本番の D1 から、決算PJ（kind=earnings）の分析動画 JSON（`fields.ev-viz-json`）99件を読み、部品で表せない場面・データの形を数えた。
そのうえで部品を足し・直し、分析 JSON から材料（ShortData）を作る変換を書いて、99件すべてに当てた（数字が壊れる件は0）。
実データ4社（ソフトバンクグループ・コアウィーブ・津田駒工業・パナソニック）で静止画を書き出して見た目も確かめた（画像は手元だけ。コミットしない）。

## 決めたこと・理由

- 材料は分析 JSON から機械的に作る（`fromAnalysis.ts`）。AI には、その会社で**使える部品だけ**を渡す（条件は `availability.ts`）。使えない部品を選ばせない。
- 配当は「（株式分割前）」「（中間）」のような注記つき、2.2倍超・半分未満の変化は出さない。保存データで、サンリオ 69円（分割前）→16円（分割後）、三井不動産 18.5円（中間）→37円（年間）のように、くらべ方が揃っていないものがあった。
- 5つの評価の呼び名は、やさしい言い方に（財務健全性 → 財務の安全性、キャッシュ創出力 → お金を生む力）。
- 「営業利益から純利益まで」は、本業と最後の利益で向きや黒字・赤字が食い違うときだけ使う（同じ向きなら決算ハイライトで足りる）。
- 事業ごとの利益で「その他」「調整額」は注目の事業にしない。
- 新しい部品も、これまでの指摘に合わせた：白地・カメラはほぼ固定・強調は色・比べるものは同じ尺度・マイナスは0の線の下。

## 気づいたが直していないこと（データ側）

- 業績の推移の数字が怪しい件がある（パナソニックの 26/3 の営業利益 2,364億円、津田駒工業で 26/11 の実績と予想が両方ある など）。推移は株探の取得値なので、部品ではなく取得の側の話。
- 会社予想の修正は、据え置き（変化なし）でも部品が使える扱い（78件）。据え置きは「進み具合」とあわせて見せる方が意味があるので、AI への指示で調整する。
